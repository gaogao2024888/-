# 万象棋助手

横屏游戏用的悬浮窗策略助手，运行在一加 Ace2 Pro（Android 15 / ColorOS 15）上。

- **第一阶段**：悬浮窗壳与交互（已完成）
- **第二阶段**：OCR 识别 + 游戏数据库 + 建议引擎（已完成，待真机验证）

---

## 怎么拿到 APK

本仓库自带 GitHub Actions，**不需要装 Android Studio**：

1. 在 GitHub 新建一个仓库（私有即可）
2. 把本目录所有文件（含隐藏的 `.github` 文件夹）推上去
3. 打开仓库的 **Actions** 页 → 左侧选「构建 APK」→ 右侧 **Run workflow**
4. 等 3~5 分钟，在运行记录底部的 **Artifacts** 下载 `wxq-assist-debug-apk`
5. 解压得到 `app-debug.apk`，传到手机安装（需允许「安装未知来源应用」）

本地有 Android Studio 的话，直接 `gradle assembleDebug` 也行。

## 本阶段已解决的问题

**✕ 不再误杀进程**
标题栏的 ✕ 只收起面板，服务和悬浮球继续运行。
完全退出要用「设置」页的「退出助手」，或下拉通知栏点「退出」。

**横屏不再过大**
默认按横屏调过：整体缩放 0.85、字体比例 0.90、面板宽度占屏 30%。
「设置」页有四个比例滑块可实时调：整体缩放 / 面板宽度 / 面板高度 / 字体比例，
另有透明度、圆角大小、实时建议间隔。改完立刻生效，无需重启。

**按钮文字自适应**
所有按钮用 `AutoFitTextView`：按钮尺寸由布局决定，文字先自动换行，
放不下再二分法缩小字号，**绝不把按钮撑大**。调整整体缩放时按钮和文字同步变化。

**识别不会串页面**
三个独立按钮（阵容 / 商店 / 天赋），各自只截取自己那块区域。
在商店页面点「识别当前阵容」不会把商店的牌算进阵容。
区域坐标按屏幕比例（0~1）保存，横竖屏切换、换设备都不错位。

**阵容与商店的分界线**
校准层里，阵容区的下边界是一条**加粗黄色虚线**，旁边标注
「▲ 以上为阵容 ▼ 以下为商店」，一眼能分清。

**日志与反馈**
「日志」页实时滚动，错误红色、警告橙色，标签上会显示异常条数。
「复制全部日志」会连同设备型号、系统版本、构建号一起复制，直接粘贴反馈即可。
已安装全局崩溃捕获，闪退的堆栈会落盘，重启后仍能看到。

**侧边把手**
屏幕边缘的细长把手，可上下自由拖动；横向拖过屏幕 1/4 会换边吸附；
单击展开/收起面板。位置按比例记忆。

**建议的两种模式**
- 实时建议：开关式，默认 1 秒一次（间隔可在设置里 300~3000ms 调）
- 识别一次并给建议：按一次只出一次结果

## 第二阶段：识别与建议

### OCR

ML Kit 中文识别，模型随 APK 打包，**完全离线不联网**。
截图后先做预处理（放大到至少 720px 宽 + 灰度 + 对比度线性拉伸），
游戏卡面是深底浅字，不预处理识别率明显偏低。

卡名匹配分三级，容忍 OCR 的多字少字：

| 级别 | 条件 | 置信度 |
|---|---|---|
| 精确 | 文本直接包含卡名 | 100% |
| 去噪 | 滤掉非中文字符后包含 | 90% |
| 模糊 | 编辑距离 ≤1（仅限 3 字以上的名字） | 70% |

模糊匹配的结果会在建议里单独标注「⚠ 可能认错」，不会混在确定结果里。

### 数据库

数据取自 [万象棋谱 WXHub](https://github.com/the-beating-light-of-the-nail/wanxiang-qipu)
（commit `ef3c25e`，数据日期 2026-09-22），裁剪成 App 需要的字段，共 88 KB：

| 文件 | 条数 | 用途 |
|---|---|---|
| heroes.json | 85 | 阶数、阵营、定位、词条 |
| camps.json | 6 | 阵营成员与 3/5 档位 |
| comps.json | 64 | 阵容匹配与推荐 |
| talents.json | 254 | 天赋三选一打分 |
| effects.json | 99 | 效果牌 |
| players.json | 18 | 棋手技能 |

### ⚠ 数据时效性（重要，务必先读）

2026-11-01 核对结果：**内置数据已经落后游戏好几个版本。**

游戏是**周更**，已确认的版本节奏：

| 版本 | 日期 |
|---|---|
| v1.5.1 | 10 月 8 日 |
| v1.6.1 | 10 月 15 日 |
| v1.7.1 | 10 月 22 日 |

而上游数据仓库最后一次提交停在 **2026-09-22**（commit `ef3c25e`），
仓库只有 `master` 一个分支，之后没有再更新。

已确认内置数据缺失的内容：

- **建木阵营** —— 10 月 7 日左右上线的第 7 个阵营，内置数据里只有 6 个
- **约 11 名新英雄** —— 随建木阵营一同登场，内置的 85 人名单里没有
- **新棋手武凤** —— 内置 18 名棋手里没有
- **天赋与效果牌文案漂移** —— v1.7.1 就调整了近 20 张天赋，
  例如「限制性进化」从给 2 张改成 3 张；天赋打分读的是描述文本，会受影响
- **英雄数值大改** —— 每周都在调，但本工具不使用任何数值，这条影响不大

**所以实际可用度**：阵营 / 阵容 / 觉醒 / 商店优先级这些**结构性逻辑仍然成立**，
因为它们依赖的是名字、阵营归属和词条，这些变动很慢。
真正的问题是**新卡完全不会被识别** —— 建木的英雄出现在屏幕上，OCR 读到了，
但库里查不到，就会被丢掉。

为此做了两层兜底：

**1. 未知卡牌会被报出来**
建议面板会显示「❓ 认出但数据库里没有：XXX」，
不会静默吞掉。你看到了就知道该补什么。

**2. custom.json 补丁层**
把 [`tools/custom.json.example`](tools/custom.json.example) 改名为 `custom.json`，
放到手机的 `Android/data/com.wxq.assist/files/data/`，
里面的英雄和阵营会追加到内置数据上。**不用重新编译 APK**，重启助手即可生效。

**3. 整体换数据**
上游仓库恢复更新后（或你找到更好的数据源），在电脑上跑：

```bash
git clone --depth 1 https://github.com/the-beating-light-of-the-nail/wanxiang-qipu /tmp/wxq
python3 tools/update_data.py /tmp/wxq app/src/main/assets/data
```

然后重新出包。也可以把生成的 JSON 直接丢进手机的
`Android/data/com.wxq.assist/files/data/`，App 会优先读外部文件。

数据超过 21 天没更新时，建议面板底部会出现过期提醒。

### 建议引擎

**识别阵容** → 列出场上英雄、各阵营距离 3/5 档还差几人、
匹配 64 套阵容给出契合度前三（核心牌权重 0.4、成员覆盖 0.6）、
标出缺的核心牌和可以下场的多余牌。

**识别商店** → 给每张牌打分排序：

| 加分项 | 分值 |
|---|---|
| 目标阵容的核心牌 | +50 |
| 补上就激活阵营档位 | +40 |
| 已有同名（推进觉醒，集满 4 张） | +30 |
| 目标阵容的成员 | +25 |
| 推进阵营进度 | +10 |
| 4 阶以上高费 | +8 |

分档显示：🔥必买(≥60) / 👍可买(≥35) / ➖看能量(≥15) / ❌先跳过

**识别天赋** → 不是无脑选高品级。基础分按品级（金30/银20/铜10），
真正的权重在联动上：天赋描述里命中场上英雄的词条 +12×该词条数量，
直接点名场上英雄 +15/个，强化目标阵容核心 +20。

> 先识别阵容，再识别商店和天赋，建议会准很多 —— 后两者依赖前者建立的场上状态。
> 新的一局记得点「重置本局」。

### 阵容屏蔽（原「禁用指定阵容」）

你之前那个工具里的同名功能不是我写的，所以按最合理的方式重新定义：

> 在「阵容」页点任意一行即可屏蔽。被屏蔽的阵容不再进入推荐排序。
> 适用场景：某些阵容理论强度高但你打不顺手，不屏蔽的话推荐位会一直被它占着。

## 风险提示

万象棋是腾讯的，带 ACE 反作弊。本工具**不读写游戏内存、不模拟点击、不抓包**，
只做截屏和画面分析，但悬浮窗 + MediaProjection 的组合仍有被判定为异常环境的可能。
**建议先用小号测试。** 风险自负。

```

├─ ProjectionRequestActivity.kt 透明中转页，只用于弹授权框
├─ Prefs.kt                     设置存储（全部按比例保存）
├─ Logger.kt                    日志系统 + 崩溃捕获
└─ UiKit.kt                     配色与尺寸工具
```
