# 中文歌词创作

## 〇、先读这一节：用户的硬性要求

这些要求都是用户在之前的对话里反复强调过的，违反任何一条都会被判不合格。

1. **类型不混。** 让写表白歌就写表白歌，让写江湖歌就写江湖歌。没被要求时，不往表白歌里加江湖味或戏腔，也不往江湖歌里加现代词。
2. **结构照用户给的来。** 用户给了结构，就一段不多、一段不少。不擅自加桥段、尾奏或前奏。用户没给结构时，用第二节的默认结构。
3. **质量比数量重要，不说废话。** 不堆词，不堆意象，一首歌一般 20 到 26 句。全曲只用一个核心意象；每句至少要是一个画面，或者推动故事；删掉流水账和口号（比如「我喜欢你就是我喜欢你」）；句子大多不超过九个字。详见 `references/作词笔记.md` 第十一节「精炼原则」。
4. **具象、有意境，不把话说满。** 用意象和代指，不直接说「喜欢你」，不要像在解释。但每句仍要念得通（见作词笔记第十四节）。
5. **不能牛头不对马嘴。** 写完用大白话把故事复述一遍，时间、季节、方向、因果都要对得上。比喻要合情理，量词和称呼要统一。
6. **先选好方法再动笔。** 交付时要说清楚：用的哪种叙事方法、副歌是哪种写法、一句话感想是什么。
7. **用户是歌词新手。** 讲解要白话，说清楚每段在干什么。
8. **不抄有版权的歌词。** 现代歌曲只借结构和方法，不整句搬。公版古诗词可以化用，但要改写。

## 一、工作流程

### 第 1 步：确认需求

确认歌曲类型、结构，以及用户有没有给旋律或字数。方向不明确时，最多问一个问题；能按默认做的，就直接做，并告诉用户你按什么默认做的。

### 第 2 步：查资料

先看 `references/作词笔记.md`，这是核心方法。然后按题材再看：
- 江湖、武侠、戏腔、古风：`references/江湖歌词素材库.md`，里面有母题、意象、可以化用的古诗、十三辙、京剧唱词句式、Suno 提示词。
- 意象：`references/意象库.md`，里面有动作的暴力、物的情绪、声音的形状三类。
- 范例：`examples/`。

用户要求时，再用 WebSearch 查补充资料。查到的资料只作参考，不抄歌词。

### 第 3 步：动笔前写下五样东西

- **歌名**：往往就是钩子。
- **一句话感想**：只要一种情绪，不能又开心又难过又遗憾。
- **叙事方法**：

  | 方法 | 适合 |
  |---|---|
  | 时间法（顺叙） | 表白、成长。表白歌结构本身就是按时间走的 |
  | 空间法 | 旅途、离别、怀念一座城 |
  | 倒叙或三明治结构（现实、回忆、现实） | 失恋、怀念、释怀 |

- **故事的地点、人物和一样贯穿全曲的小东西**：只要一个地点、一个人、一样东西，用小事写大事。
- **意象清单**：每个意象都要写成「物加处境」（比如「冷雨」，不是「雨」）。避开流星、烟火、沧海这类烂大街的意象。

### 第 4 步：先写副歌

- 副歌的任务：点题、重复情绪、放金句、高度概括。
- 副歌只抒情，不讲故事，不铺细节，不交代时间、地点、人物。
- 句子要短，能循环，好记好唱。
- 选一种写法：直抒胸臆、金句总结、呐喊反问或假设、释怀放手。
- 必须有一句能单独拿出来的金句。
- 副歌第一句放钩子，最好就是歌名，同时交代核心的东西。
- 两遍副歌钩子不变，最多只改一句（通常是最后一句），靠前面的主歌和预副歌让意思翻转。
- 最后一遍副歌的末尾，可以把钩子或最后一句再唱一遍收尾。这一段不另外加段落标签。（详见作词笔记第十三节）

### 第 5 步：写主歌和预副歌

- **主歌**：写场景和小动作，用名词加动词。不写伤心、想你、爱你这类空词，展示，不说教。
- **主歌 2**：情绪往前推一步，可以从写场景转到写人。
- **预副歌**：情绪慢慢推高，快爆发但还没爆发。两遍预副歌最好前后呼应，比如第一遍不敢说，第二遍说出来了。
- **口语化**：国风和戏腔也要一句诗词，紧跟一句口语，把听的人拉回来。
- **炼字**：每句写完问自己「新手会怎么写？」。如果写出来的就是新手写法，就用动词嫁接或更有张力的动词换一次。但换完的句子必须意思通、念得顺，不能为了奇而奇。

### 第 6 步：交稿前自查

逐条过 `references/作词笔记.md` 最后的检查清单，要点如下：

1. 副歌有没有在叙事？
2. 主歌有没有抽象的情绪词？
3. 形容词能不能换成动词和名词？
4. 比喻是新的、合理的吗？
5. 押韵有没有硬凑？可以隔句押、只押副歌，也可以用宽韵。
6. 用大白话复述一遍：故事接得上吗？
7. 每句大声念一遍：通不通顺？副歌单独拿出来看不看得懂？动作有没有对象（写的是什么）？「那个」「它」这类指代清不清楚？（详见作词笔记第十二节）
8. 有没有堆词？删掉不推动故事的句子。
9. 风格有没有混？结构是不是用户要的？

### 第 7 步：交付

1. 歌词放在代码块里，带 Suno 段落标签，比如 `[Verse 1]`、`[Pre-Chorus]`、`[Chorus]`。不用圆括号，Suno 会把括号里的字唱出来。戏腔段可以写成 `[Bridge: Peking opera vocal]` 这样。
2. 说明写法：一句话感想、叙事方法、副歌写法、金句、前后呼应，再列一张表，写清每段做了什么，最后附上大白话复述。
3. 给出 Suno 风格提示词。
4. 内容多就另存一个 Markdown 文件。

## 二、常用结构

- **表白歌（用户指定的默认结构）**：主歌 1（遇见的场景）、预副歌（心动但不敢说）、副歌（我喜欢你）、主歌 2（相处的小细节）、预副歌（决定勇敢一次）、副歌（再次大声表白）。
- **新手最简单的结构**：主歌 1、主歌 2、副歌，再重复主歌 2 和副歌。
- **每段的作用**：
  - 前奏：定氛围，没有歌词。
  - 主歌：讲故事，情绪平静克制。
  - 预副歌：情绪爬坡。
  - 副歌：全歌的灵魂。
  - 桥段：反转或醒悟，情绪再升一级。
  - 尾奏：留白。

  只在用户要求时才加前奏、桥段、尾奏。

## 三、有旋律时：按旋律填词

用户给了音频、MIDI 或 Suno 歌曲，就用 `scripts/melody_lyrics.py` 走一遍。下面命令里的 `ml` 指 `uv run <本技能目录>/scripts/melody_lyrics.py`；没有 uv 就先 `pip install librosa soundfile mido pypinyin`。

```bash
ml info 歌.mp3                                      # 读歌名、风格提示词
ml extract 歌.mp3 -o 歌.melody.json                  # 扒主旋律
ml sections 歌.melody.json                          # 分人声段和器乐段；女声加 --voice female
ml lines 歌.mp3 歌.melody.json --section 主歌1=15.9 -o 歌.spec.txt   # 每句字数和简谱
ml template 歌.spec.txt -o 模板.json
ml check 模板.json 歌词.txt                          # 查字数、韵脚、倒字
ml rhyme 歌词.txt --ref 1                           # 查单押、双押、三押
```

字数以 `check` 的结果为准，不要自己数。押韵、十三辙、倒字的细节看 `references/rhyme-and-tone.md`，按旋律填词的方法看 `references/melody-writing-method.md`。没有旋律时，字数按常见的句式写，交付时说明还没有对过旋律。
